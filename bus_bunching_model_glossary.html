Bus Bunching Model Glossary

Plain-language definitions for the bus bunching prediction model and report.

This glossary explains the terms used in the bus bunching model report. The model is intended to help identify route-hours with higher bunching risk, not to guarantee that a specific bus trip will or will not bunch.

Core Bus Bunching Terms

Bus bunching
When buses that are supposed to be spaced apart arrive too close together. This can create uneven service, longer waits for some riders, and inefficient vehicle spacing.
Bunching event
A recorded instance where buses were close enough together to meet the bunching threshold used in the analysis.
Deduped bunching episode
A cleaned-up count of bunching that avoids counting the same pair of buses repeatedly as they move through multiple stops. This is the main event count used by the model.
Scheduled stop arrivals
The number of scheduled bus arrivals represented in a route-hour. This is used as the denominator so high-service and low-service periods can be compared fairly.
Bunching rate per 100 scheduled arrivals
The number of deduped bunching episodes divided by scheduled stop arrivals, multiplied by 100. This turns bunching into a rate that can be compared across routes and hours.
Route-direction-hour
The basic unit of the model: one route, one direction, on one date, during one hour. Each row in the model represents one route-direction-hour.
Model row
One observation used by the model. In this project, each model row is a route-direction-hour with service volume, observed bunching, and any available external conditions.

Data Sources

Historical bus bunching data
The recent observed bus bunching events used to teach the model where and when bunching has happened before.
Weather data
Hourly citywide weather history, including temperature and wind speed. It is useful for screening broad weather conditions but does not capture block-by-block conditions.
MVI calls
Seattle Fire motor vehicle incident calls. In this model, MVI exposure is approximate because calls are matched using available time and street-name information rather than exact route-level incident geometry.
KCM advisory
A King County Metro service advisory observed in the advisory feed. In this model, advisory timing is based on when the advisory was captured, not a complete start-to-end advisory history.
External inputs
Conditions outside the historical bus schedule and bunching pattern, such as weather, MVI activity, and KCM advisories.
Coverage
How much of the model period has usable data from a source. For example, weather, MVI, and KCM advisories do not all cover the full bus bunching date range equally.
Missing coverage vs. observed zero
Missing coverage means the source did not provide usable data for that row. Observed zero means the source was available and showed no relevant activity. These are different and should not be interpreted the same way.

Model Training and Testing

Model
A repeatable scoring method that learns patterns from past data and applies those patterns to estimate future or current bunching risk.
Training/control period
The earlier dates used to learn the model weights. In the current report, this period is 2026-07-22 to 2026-08-01.
Validation/trial period
The later dates held back from training and used to test the model. In the current report, this period is 2026-08-02 to 2026-08-04.
Holdout test
A test where the model is trained on one set of dates and evaluated on later dates it did not use for training. This is a practical check on whether the model generalizes beyond the data it learned from.
Historical baseline model
The model that uses route, direction, hour, and scheduled service volume to predict bunching risk. In this project, this performed better on the validation period than adding external inputs.
External-parameter model
A model that adds weather, MVI, and KCM advisory information to the historical baseline. These inputs were tested, but they did not improve the validation result in the current sample.
Pilot model
An early model that is useful for screening and learning, but should be refined as more overlapping event and external-condition history becomes available.

Model Outputs

Predicted bunching rate
The model's estimated bunching episodes per 100 scheduled arrivals for a route-direction-hour.
Risk decile
A 1-to-10 ranking of predicted risk. Decile 10 is the highest predicted risk group; decile 1 is the lowest predicted risk group.
High-risk route-hour
A route-direction-hour with a high predicted risk score. These are good candidates for dispatch monitoring, schedule reliability review, or targeted operational analysis.
Model weight
The amount the model moves the risk estimate up or down when a route, hour, or condition is present. Larger positive weights increase predicted risk; negative weights reduce predicted risk.
Rate multiplier
A more readable version of a model weight. A multiplier above 1 means the model increases predicted risk; below 1 means it lowers predicted risk.

Correlation and Performance Terms

Correlation
A measure of whether two things tend to move together. In this project, correlations were used to screen whether weather, MVI, or advisory inputs appeared to line up with bunching.
Spearman correlation
A correlation method that looks at whether higher values of one input tend to go with higher or lower bunching rates. It is useful when the relationship may not be a straight line.
Additive effect
The difference in observed bunching rate between two groups, such as periods with an advisory and periods without an advisory.
Calibration
How well predicted risk lines up with actual observed bunching. A useful risk model should generally show more bunching in higher-risk groups than in lower-risk groups.
Weighted MAE
Weighted mean absolute error. This is the average size of the prediction error, weighted so route-hours with more scheduled arrivals count more than route-hours with very little service.
Weighted RMSE
Weighted root mean squared error. This is another error measure that gives more penalty to larger misses.
Overfitting
When a model learns patterns that fit the training dates but do not work well on later dates. Holding out validation dates helps guard against overfitting.

How to Read the Results

"It works well"
In this report, this means the model is useful for ranking and prioritizing risk. The highest-risk decile captured a large share of validation-period bunching, so the model helps focus attention on the route-hours where bunching was most concentrated.
"External inputs were not selected"
This does not mean weather, MVI calls, or advisories never matter. It means they did not improve the held-out validation result after the model already accounted for historical route, direction, hour, and service-volume patterns.
Recommended use
Use the model as a screening and prioritization tool. Review deciles 8-10 first, especially decile 10, for dispatch monitoring, schedule reliability checks, or deeper investigation.
