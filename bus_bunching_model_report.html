Bus Bunching Prediction Model Report

Route-direction-hour pilot model using deduped bunching episodes and scheduled stop arrivals.

Top line: this is a practical bus-bunching risk model. It is strongest as a prioritization tool: it identifies the route-hours most likely to have bunching, so staff can focus monitoring and operational review where risk is highest. The baseline model was selected because the external parameters did not improve held-out weighted MAE. The external inputs were not selected for the final score because they did not improve the holdout test.

1. Executive Summary

What we did: We assembled recent bus-bunching history, scheduled service volume, weather, Seattle Fire MVI calls, and KCM advisory records into one modeling dataset. Each row represents one route, one direction, one date, and one hour.

What the model does: The model learns which route-hours have historically been more likely to bunch, then assigns each future or current route-hour a predicted bunching rate and a risk decile from 1 to 10.

Why it is useful: On the held-out trial dates, the highest-risk decile captured 63.9% of observed bunching episodes while representing 18.0% of scheduled arrivals. That means the score is useful for narrowing attention to the route-hours where bunching is most concentrated.

The bus-bunching file covered 14 service dates. We converted it into route-direction-hour records so that each model example represents a practical planning or operations unit. The target is deduped bunching episodes per 100 scheduled stop arrivals.

Deduping matters: one pair of buses can stay bunched across multiple stops. Counting every stop-level sighting as a separate event would exaggerate the problem. This model uses deduped episodes so the result is closer to the actual number of bunching occurrences.

3. What the Model Is

The model is a risk scoring model, not a guarantee that a specific bus will bunch. It scores each route-direction-hour based on what happened historically and returns two outputs that are easy to use:

  • Predicted bunching rate: expected deduped bunching episodes per 100 scheduled arrivals.
  • Risk decile: a 1-to-10 ranking where 10 is the highest predicted risk group.

In this version, the model learned that historical route, direction, hour, and amount of scheduled service were the most reliable predictors. Weather, MVI calls, and advisories were tested, but they did not improve the trial-period prediction once the historical route-hour pattern was already included.

4. Why the Model Works Well

The model works well for prioritization because the high-risk scores are where the observed validation-period bunching was concentrated. On the trial dates, the highest-risk decile had an observed bunching rate of 0.548 episodes per 100 scheduled arrivals, compared with 0.004 in the lowest-risk decile.

Model training means the script estimates weights from the training/control dates, then asks: if we had used those weights on the later validation/trial dates, how close would the predictions have been? The main error statistic below is weighted by scheduled arrivals, so busy route-hours count more than route-hours with very little service.

5. How We Got There

1
Create clean examples
Each example is one route, direction, date, and hour. The answer the model learns is how many deduped bunching episodes happened per 100 scheduled arrivals.
2
Look for signals
Weather, MVI activity, and KCM advisories are screened to see whether they move with higher or lower observed bunching.
3
Learn weights
The model learns which route, direction, hour, and service levels historically have more bunching, then tests whether external signals add useful information.
4
Test later dates
The latest dates are held out as a trial. A variable is useful only if it helps predict those later dates, not just if it looks related in the training data.

6. Correlation Screen

This is the screening step before model fitting. It answers: "Do alerts, weather, advisories, or MVI calls appear to line up with bunching?" Positive Spearman means bunching tends to be higher when the input is higher or present. Additive effect is the difference in actual bunching episodes per 100 scheduled arrivals between the comparison groups. These correlations help decide what to test in the model; they are not the final weights by themselves.

7. How Good Is the Model, and What Comes Next

The main point is simple: the model learned that recent historical route-hour patterns were more useful than the available external inputs for predicting the held-out trial dates.

The best evidence is how the model ranked risk on the validation/trial dates. The highest-risk decile captured 63.9% of observed bunching while representing 18.0% of scheduled arrivals. That means the model is useful for narrowing attention to the route-hours where bunching is most likely to show up.

How to Use the Model

To use the model for prediction, create the same route-direction-hour rows for a future or current day, fill in scheduled arrivals plus available weather/MVI/KCM inputs, and run this script. The output is a predicted rate and a risk decile.

The main use case is not to say that one specific trip will definitely bunch. The main use case is to focus attention. Route-hours in the highest risk deciles should be reviewed first for dispatch monitoring, schedule reliability checks, operator relief planning, or deeper analysis of recurring trouble spots.

Recommended interpretation: Treat deciles 8-10 as elevated risk, with decile 10 as the first place to look. Treat deciles 1-3 as lower priority unless there is a separate operational reason to review them.

Next Steps: Turning This Into Prediction

The current model is a validated pilot risk model. To turn it into a repeatable prediction process, the next step is to make this a weighted model workflow that can score future route-hours and then measure how well the prediction worked after actual bunching outcomes are observed.
